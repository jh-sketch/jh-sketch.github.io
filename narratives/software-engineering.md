## Artifact Description
The artifact I selected for my algorithms and data structures enhancement is the Pirate Intelligent Agent, which I originally developed around August 2026 for CS 370: Current and Emerging Trends in Computer Science. The original project used Python and deep Q-learning (DQN) to train a pirate to move through an 8-by-8 maze and find the treasure. The agent learned from rewards and penalties as it moved through the maze. It also used a neural network, experience replay, and testing functions to determine whether the pirate could reach the treasure from different starting positions.
When I first worked on this project, I spent a lot of time troubleshooting the training process. I didn't quite understand how everything worked or how to get the different parts of the program working together. At one point, the agent reached a 100% training win rate but still failed its completion check. After reviewing how the program selected actions and handled the end of a game, I corrected those issues and eventually passed the completion check. That experience was one reason I chose this project for my capstone. I felt there was still more for me to learn, and I wanted to do more than show that the pirate could reach the treasure. I wanted to evaluate how efficiently it could get there.
## Justification for Inclusion and Artifact Improvements
I included the Pirate Intelligent Agent in my ePortfolio because I felt it was different from many of the other projects I worked on during my computer science program. It introduced me to artificial intelligence and machine learning, which I believe will become increasingly important in software development. This project helped me develop a basic understanding of how machine learning works and how an intelligent agent can learn from experience.
I also selected this artifact because I wanted to demonstrate my ability to work with algorithms and data structures while improving a project that I originally found challenging. I believe the experience of revisiting an existing project and making improvements is an important part of becoming a software developer.
One of the main improvements I made was adding the A* pathfinding algorithm to the existing project. In my code review, I discussed breadth-first search as one possible way to find a shortest path. My later enhancement plan selected A* because it can also find shortest paths in this maze while allowing me to demonstrate heuristic search. Unlike DQN, which learns through training, A* uses the known maze layout to calculate a route to the treasure.
I added a method to identify valid neighboring cells and implemented A* using a heap-based priority queue, dictionaries to track movement costs and previous positions, and the Manhattan distance heuristic. The pirate moves in four directions, so Manhattan distance provides an appropriate estimate of the remaining distance.
I also added a visualization of the route and automated tests covering blocked starting positions, legal movements, unreachable treasure, and valid starting positions. All five automated tests passed. While reviewing the supporting code, I corrected how invalid movements were handled in TreasureMaze and updated the experience-replay logic so terminal states are treated differently from unfinished games.
Another improvement was retraining the DQN model and saving it as pirate_dqn.keras. The new training run passed the completion check at epoch 275, with a reported training time of 164.4 seconds. I also loaded the saved model separately and confirmed that it passed the completion check again. This allowed me to reuse the trained model for testing without repeating the entire training process.
The specific components of this artifact that showcase my skills include the A* implementation, the use of priority queues and dictionaries, the automated tests, and the comparison between DQN and A*. These demonstrate my understanding of algorithm design, data structures, Python programming, problem-solving, and performance evaluation.
One of the biggest improvements was adding a way to measure how efficiently the pirate navigated the maze rather than focusing only on whether it reached the treasure.
Both algorithms successfully reached the treasure from all 50 tested starting positions. DQN took an average of 15.96 moves, compared with 15.64 for A*, a difference of 0.32 moves per starting position. From the top-left corner, both algorithms took 24 moves. This showed that the trained DQN agent had learned routes that were close to the shortest paths calculated by A*.
The comparison also helped me understand that different algorithms can solve the same problem in different ways. A* uses the known maze layout to calculate a route, while DQN learns a policy through experience. The results compare path lengths and success rates rather than directly comparing DQN training time with A* execution time.

With an appropriate heap-based priority queue implementation, A* can have a time complexity of O((V + E) log V), where V represents locations and E represents possible movements. Its memory requirements depend on how many locations and candidate paths are stored during the search. ## Reflection on the Enhancement Process
One of the most important things I learned from this enhancement is that successful results do not always tell the whole story. In my original project, I was focused on getting the agent to pass its training and completion checks. For CS 499, I wanted to look more closely at the quality of the solution. Adding A* gave me a shortest-path benchmark, and comparing the movement counts helped me see how well the trained DQN agent performed beyond simply reaching the treasure.
I enjoyed visualizing the A* route and seeing how the algorithm avoided obstacles. Getting the search to handle blocked cells and reconstruct a valid path took some troubleshooting, but the automated tests helped me confirm that the changes were working.
Retraining DQN on my Mac also presented challenges because I had to set up the Python environment and make sure the original functions and dependencies were loaded correctly. Saving and reloading the trained model was another improvement to my workflow.
During the enhancement process, I used the problems I identified in my original code review to guide my improvements. One of the main limitations I noticed was that the program could determine whether the pirate reached the treasure, but it did not evaluate whether the route was efficient. This helped me decide to implement A* and compare its results with DQN.
I also used my automated tests, and completion checks as feedback on whether the changes were working correctly. When something did not behave as expected, I reviewed the code, made corrections, and tested it again. This process helped me understand the importance of evaluating software after making changes. I also plan to incorporate any additional feedback from my instructor before completing my final ePortfolio.
The new DQN model passed its completion check at epoch 275, compared with epoch 635 in my original CS 370 run. I would not claim this proves that the new code trains faster because training involves randomness, and the environment and software setup changed. What I can show is that both algorithms succeeded from all 50 starting positions and that DQN averaged only 0.32 more moves than A*.
Overall, this enhancement helped me better understand algorithms, testing, and the importance of evaluating different solutions.
